# 0.6.0 画像からの原稿作成

2026-11-03。versionCode 22。ローカル実装・検証の記録です。GitHubへの公開は行っていません。

## 操作と保存

停止中のメニュー「読み上げ原稿作成」から、Androidの画像選択画面を開きます。選択結果の順番をそのまま取り込み、追加した画像は末尾へ置きます。生成前にサムネイル、↑・↓、削除、画像を追加で内容と順番を確定できます。

「生成」でアプリ専用領域へコピーし、向きを反映したPNGを `001.png` から連番で作ります。元画像のURIに書き込み・名前変更・削除を行いません。すべての変換と空の `script.txt` の作成後に、アーカイブの記録を確定します。途中で失敗した場合は今回の作業用フォルダーを除去し、選択状態を保って再試行できます。以前の資料は保持します。

作成画面は上に1枚のスライド、中央に横スクロールする文字列ボタンと右端の設定、下にそのページの入力欄を置きます。「前へ」「次へ」でスライドと入力欄を一緒に切り替え、各ページの本文とカーソル位置を保持します。`##番号` は画面に表示し、保存時に自動で組み込みます。

文字列ボタンは選択範囲を置き換えるか、カーソル位置へ文字列をそのまま挿入します。初期値は `[任意の文字列(mm:ss)]` と `**コメントアウト`。右端のメニューで内容の編集、追加、削除、前後移動ができ、「適用」で端末内に保存します。空のボタン一覧も保持し、再起動時に初期値を再追加しません。

「保存」は全ページをまとめて保存し、画面を閉じません。本文のないページも保存できます。書式やスライド番号に誤りがある場合は直前の保存内容を保持し、エラーを表示します。時間区間の `mm:ss` は有効な時刻へ書き換え、単独行に置きます。読まないメモは行頭に `**` を置きます。

未保存の変更がある「閉じる」・戻る操作では「保存する／保存しない／キャンセル」を表示します。保存して閉じる処理に失敗した場合は画面に残ります。生成済みの画像と最後の保存内容はアーカイブに残り、未保存の本文だけを破棄します。作成中の資料へ発表画面を自動切替しません。アーカイブから開いて持ち時間を設定すると練習できます。再編集は既存のアーカイブの鉛筆による全文編集を利用できます。

## 上限と互換性

画像200枚、入力画像と出力PNG各24MiB以下、40MP以下、出力画像合計256MiB以下、原稿UTF-8で2MiB以下。原寸で変換し、上限超過・破損・アクセス失効はエラーにします。変換に必要なメモリを確保できない場合も選び直しを案内します。

Android 8以降に対応し、画像の向きはAndroid 8ではAndroidX ExifInterface、Android 9以降ではImageDecoderで反映します。選択前のサムネイルも同じデコード処理を使用します。既存の資料・画像・ZIP・設定は自動変換しません。初回サンプルの追加条件、通常の発表画面とFoldの2列配置は保持します。

画像選択には画像だけを対象とするPhoto Pickerと、利用できない端末での標準フォールバックを使用します。選択順を要求しますが、端末側の実装によっては対応しないため、生成前に順番を確認できます。[Android公式API](https://developer.android.com/reference/androidx/activity/result/PickVisualMediaRequest.Builder#setOrderedSelection(boolean))にもこの制限が示されています。選択画面から返った順序をアプリ側でファイル名順等に並べ替えることはありません。

OSによるプロセス終了では未保存の原稿や画像選択は復元しません。実機でのメディア選択、キーボード、上書き更新、Fold開閉、振動は未検証です。Dropboxへのローカル保存と同期完了は区別します。
